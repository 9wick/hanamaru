# 期待と観測

期待はtargetの契約に基づいて書きます。具体値、部分、性質、関係、状態、actionは用途を区別し、その用途で成立する条件だけを指定できます。[UX/DX契約](../guides/testing-contracts.md)に従い、すべてを任意のbooleanや汎用マッチャへ変換する入口は設けません。

[各入口の完結したコード例と禁止例](../guides/writing-tests.md)が公開構文です。expect / property / relateを使い分けます。

## result

戻り値の型は対象の `Awaited<ReturnType<F>>` から推論します。具体的な正解があるケースでは、その期待値を直接指定します。

```text
対象: add
入力: 1, 2
結果の期待: 3と等しい
```

値の一致と参照の同一性は区別します。具体値の欄に「0ではない」や任意述語を渡して代用することはできません。Result型の失敗値も正常な戻り値として扱います。

## 部分・性質・関係

| 方法 | 記述するもの | 制約 |
|---|---|---|
| 部分検証 | 出力のどの部分を観測し、何と一致すべきか | 出力全体の一致として報告しない |
| 性質 | 対象の入力・結果・観測値と、成立する条件 | 具体値の期待の欄へ持ち込めない |
| 関係 | 入力・複数の結果・観測値の参照と、その間の条件 | 別ケースの参照や未実行の値を持ち込めない |

標準で表せる条件は対象参照を持つ記述にします。独自の性質に必要な述語は、その性質の入口で扱います。述語の例外は検証処理の失敗であり、targetに期待した例外ではありません。

## error

throw/rejectを期待するケースは、契約が定める例外の種別・内容を指定します。正常結果の期待とは両立しません。

```text
対象: 登録処理
入力: 契約上拒否される登録情報
例外の期待: 登録拒否を示す種別と内容
副作用の期待: targetの失敗時の契約に従う
```

スタックや生成位置の完全一致を要求しません。「特定のエラーではない」だけで期待する失敗を指定したことにはなりません。準備・観測・検証・後始末の例外や実行timeoutは、targetの期待した失敗として成功にできません。

## 状態

実行後の状態、実行前後の変化、不変を区別します。取得関数などの観測手段を指定し、その結果型から期待値を推論します。

```text
対象: 名前の更新
実行前の観測: ユーザーの住所
実行後の観測: ユーザーの名前と住所
期待: 名前は指定値、住所は実行前と同じ
```

実行前の値を独立して保持し、同じ可変参照を前後のスナップショットにしません。取得できなかったことを、不在や空の状態と同一視しません。状態が前後で同じでも、途中のactionがなかったとは判定しません。

## action

メール到着など、targetの責任として外部に生じる出来事を観測します。target開始前に観測を開始し、今回の試行の対象・期間・完了条件を指定します。

内容・個数・順序は契約に必要なものだけを期待します。過去や別ケースの出来事を混入させません。観測の待機ではtargetを再実行しません。

## 否定

否定は用途に即して表します。関係では「二つの参照が異なる」、状態では「値が変わらない」、actionでは「指定区間に発生しない」を扱います。全マッチャを一律に反転する共通notは提供しません。

不発生には有限の観測期間または契約に対応する完了条件が必要です。一度の未観測から、無期限の不発生を報告しません。観測器や述語が失敗したときに、その失敗を反転して成功にすることもありません。

## 呼び出し

効果を直接観測できないときは、環境が許可したinfra境界への呼び出しを代替の証拠として確認できます。対象の範囲は[infra境界](api-mock.md)で定めます。

引数・回数はその境界の型と契約から指定します。呼び出し記録は実際のメール到着や保存状態を示す記述子には変換できません。内部の任意メソッドを指定するspyは提供しません。呼び出し記録だけでは対象の実行を止めないため、環境の選択と境界の代替は別に指定します。

## middlewareで生成した参照・値を検証する

環境が提供する観測器・許可済み境界・期待値は、middlewareのコンテキストから取得できます。試行ごとに解決し、観測や記録が必要なものはtarget実行前に準備します。

任意オブジェクトをctxへ入れるだけでは、内部関数への介入を許可したことにはなりません。観測器が読み取った状態と、その取得関数への呼び出し記録も区別します。

## コンテキスト

入力・観測先・期待値へ必要な型はコンテキストから推論します。観測の期間や実行前後の値は実行器が試行へ結び付けます。利用者がctxに可変参照を置いただけで、実行前の状態が保存されたことにはしません。

## 期待値の保存

toEqual・partのtoEqual・action全件一致の期待値はcompile時に独立した値として保存し、targetによる入力変更に追従させません。[スナップショットの値領域](../guides/writing-tests.md#スナップショットの値領域)を満たさない値はcompileの失敗です。toBeとLiveRefによる参照比較は参照自体を扱うためコピーしません。

value・input・resultを性質や値の関係で使う場合も、[取得時点](../guides/writing-tests.md#値の取得時点と参照同一性)で保存した値を読みます。後続操作の変更で先行結果や比較対象を変えません。

## 深い一致と評価

値の比較基準は、具体値と部分検証で区別して定めます。期待値・実測値の型を保持し、文字列化した見た目だけで比較しません。参照の同一性は値の一致と別の条件で、input/result/valueのLiveRefだけを受け付けます。コピー済みのstate/before/actionのSnapshotRefは型とcompileで拒否します。

診断では、対象・入力・期待・実測と、失敗した条件を示します。取得不能、条件の不一致、述語の例外、未評価を区別します。関係の失敗には双方の値、状態には観測時点、actionには期間・完了条件を残します。代替したinfra境界と呼び出し記録による検証も識別できます。
