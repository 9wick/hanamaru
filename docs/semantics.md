# 実行セマンティクス

このページは `run(plan)` が実行する契約です。
ランナーは未実装であり、ここに記載する実行時保証は実装・検証対象です。

## 定義と実行の境界

`new Test()` のチェーンは、itとmockの定義コールバックを評価して計画を組み立てます。
expectのコールバックは保存し、この時点では呼びません。
`.plan()` は計画を取得し、`run()` が実行します。
setup・target・argsFrom・fake・述語も、計画取得だけでは呼びません。
テストモジュールのトップレベルコードは通常のimportと同様に動きます。

## 計画の受付

```ts
const result = await run(tests.plan())
const results = await run([first.plan(), second.plan()])
```

単一計画または計画配列を受け取り、渡された順・ケースの宣言順に直列実行します。
結果のtestsは計画と同じ順で、各結果のcasesは計画のケースと同じ順・同じ件数です。
skip/todoも結果に残すため、名前が重複していても配列の位置で対応します。

versionや計画構造を実行前に検査します。空の計画配列は受付エラーです。
受付エラーではsetupを開始せずPromiseをrejectします。ケース中の失敗は結果に残し、他のケースを続けます。
同一プロセスで複数のrunが重なる場合も受付エラーにします。

## 1ケースの手順

1. **setup**: createを呼び、Promiseならawaitしてctxを得る。省略時は新しい `{}`。
2. **mock**: 登録先を検査し、元のプロパティdescriptorを退避してモックを適用する。
3. **args**: 静的な引数を使うか、argsFromにctxを渡して引数タプルを得る。
4. **target**: 対象を呼び、Promise/thenableならawaitする。戻り値か例外をタグ付きで保持する。
5. **expect**: ctxと記述子ビルダーで期待の配列を作り、その構造と参照を検査する。
6. **assertion**: 配列から期待する終了を判定し、実際の終了と各アサーションを照合する。
7. **cleanup**: finallyでモックを逆順に復元し、disposeがあればctxを渡してawaitする。

setup中はモックを適用しません。呼び出し記録は適用後に開始し、targetの終了時に止めます。
argsFromでモックを呼んだ場合は記録に含まれるので、argsFromは引数を作る処理に留めます。
期待の構築・アサーション・後始末中の呼び出しは検証する記録に含めません。
expectのコールバックと各述語は、それぞれ1回だけ呼びます。

## 正常終了・例外の期待

返された配列にerrorの記述子があれば例外、なければ正常終了を期待します。
resultとerrorの混在、空配列は型エラーであり、実行時にもケースの失敗とします。

| 期待 | 実際 | 結果 |
|---|---|---|
| 正常終了 | 正常終了 | resultとmockの条件を検証 |
| 正常終了 | throw / reject | 予期しない例外として失敗 |
| 例外 | throw / reject | errorとmockの条件を検証 |
| 例外 | 正常終了 | 例外が発生しなかったとして失敗 |

モックだけを検証するケースにも正常終了の検査があります。
`return undefined` と `throw undefined` は別の結果です。例外の有無を値の真偽で判定しません。

終了の種類が合わなくてもモックの検証は続けます。
存在しないresult/errorを必要とするアサーションは評価不能として報告し、述語を呼びません。
述語がthrowした場合はそのアサーションの失敗として残し、他のアサーションを続けます。

## 途中の失敗

| 失敗した段階 | 扱い |
|---|---|
| setup | targetを呼ばない。ctxを得ていないのでdisposeも呼ばない |
| mockの適用 | targetを呼ばず、適用済みモックの復元とdisposeを行う |
| args | targetを呼ばず、モックの復元とdisposeを行う |
| target | 戻り値 / 例外として保持し、期待と照合する |
| expectの構築・妥当性検査 | ケースを失敗にし、後始末する |
| assertion | 失敗を記録し、後続を検証して後始末する |
| cleanup | 元の失敗も残し、残りの復元とdisposeを試みる |

setup・mock・args・expect・cleanupの失敗は、targetに対するerrorの期待を満たしません。
setupの途中で取得した資源は、create自身で後始末します。

## モックの適用と復元

共通設定とケース設定を、オブジェクト参照・キーの一致で解決します。
同じ組への再登録は振る舞いを上書きし、最初の登録位置を保ちます。その実効一覧の順で適用します。
`target(object, key)` と同じ登録先へのmockは、対象自体の差し替えになるためエラーにします。

書き換え可能なデータプロパティ、またはshadow可能な継承メソッドを対象とします。
アクセサ、非関数、差し替え不能なプロパティはエラーです。
復元では元のdescriptorを戻し、継承メソッドをshadowした場合は追加したown propertyを削除します。

復元の契約はfinallyへ到達する実行を対象とします。
強制終了や終了しないtargetでは後始末を開始できず、外部コードの凍結等で復元できなければ失敗として報告します。

## ケース間の状態

ケースごとにsetupを呼び、呼び出し記録を作り直します。同じ計画の再実行でも同様です。
静的に渡したオブジェクトや、factoryが返した共有値まで複製はしません。
独立性が必要な値はsetupやargsFromで毎回生成してください。

## only / skip / todo

runに渡された計画全体のどこかにonlyがあれば、onlyだけを実行します。
他のrunケースはskipped、明示skipはskipped、todoはtodoとして結果に残し、setup・targetを呼びません。
定義時のit/skipコールバックは計画を組み立てるために評価します。

`run(plans, { forbidOnly: true })` はonlyを受付エラーにします。
CLIの `--ci` はこの設定を使います。通常実行ではskip/todoだけでも失敗としません。

## 結果

`RunResult` は計画順のtestsを持ち、各TestResultのcasesにはケース名・状態・所要時間・失敗一覧が入ります。
失敗には発生段階を記録します。実際の戻り値・例外の全体をJSONに埋め込むことは要求しません。
表示と終了コードは[CLI](./cli.md)を参照してください。
