# テストの登録

CLIで実行するルートは `registerTest` で明示します。登録はテストファイルを読み込むときの副作用です。完成定義をexportしただけでは実行しません。`registerTest` を呼んでも、その場でテストやmiddlewareは実行しません。

## CLIに実行するルートを伝える

<!-- example: none — 登録の最小例 -->
```ts
import { Test, registerTest } from 'hanamaru'
import { add } from './math.ts'

registerTest(
  new Test()
    .target(add)
    .it('2つの数を足す', t => t.args(1, 2).expect(e => [e.result.toBe(3)])),
)
```

CLIは選んだファイルを読み込み、そのファイルに書かれた `registerTest` の登録をルートとして収集します。ファイルに複数のルートを登録できます。登録したルートをexportする必要はなく、exportによる収集へのフォールバックもありません。importした別ファイルの登録は、そのファイルも収集対象に選ばれていない限り、実行対象には加えません。

`registerTest(root: TestDefinition<{}>): void` を公開型とします。親の供給が必要な子を単独で登録するとTypeScriptの型エラーになります。子は親の `.group()` に渡し、供給を含む完成したルートを登録します。子を親のファイルからimportするためのexportは使えますが、そのexport自体はCLIの実行対象を増やしません。

CLIはTypeScriptの型検査を行いません。型による登録条件は、利用者が型検査を実行したときに働きます。`any`・型アサーション・JavaScriptなどで要求ctxを隠した場合、CLIが未供給のctxを実行前に判定する保証はありません。日常のコマンドには[型チェック](../reference/cli.md#型チェックを含む通常の入口)を含めます。

## 収集時の診断

選んだテストファイルに登録されたルートがなければ、CLIは収集エラー（終了コード2）で停止します。選んだ全ファイルの登録と実行計画を確認してからfilterやonly・skip・todoを適用し、その後に必要なmiddlewareを開始します。未完成の値や同じルートの重複登録も収集エラーです。

選んだファイルで評価された完成定義のうち、登録ルートでもその子でもチェーン途中の値でもないものは「野良test」として警告します。exportの有無は判定条件にしません。評価されなかったコードまで検出する保証はありません。

登録を保持する範囲は一回のCLI収集です。実行workerでも同じファイルを読み込んで登録を再現し、収集時に決めたルートと対応させます。別のRunに登録を持ち越しません。

## projectと直接実行との関係

[project](projects.md)は、CLIがどのファイルを読むかを名前で選ぶ機能です。各projectの `include` / `exclude` にファイルパスやパターンを指定し、選んだファイルの登録を収集します。projectがなくてもCLIの既定探索やファイル指定で登録されたルートを収集します。

自分のプログラムから定義を直接実行して結果を受け取りたい場合は、既存のライブラリAPI `run(test)` を使います。`run` は登録台帳・ファイル探索・project選択を使いません。projectの設定やテストファイル内で `run()` を呼ぶ必要はありません。
